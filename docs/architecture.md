# Архитектура фронтенда

Next.js с App Router рендерит каталог и карточки на сервере. React-компоненты показывают серверные избранное и оценки выбранного профиля. Браузер обращается к Next.js, а Next.js — к FastAPI по серверному BACKEND_API_URL.

## Каталог

`src/api/catalog.ts` получает популярные подборки и поиск через `GET /api/v1/discovery/movies`. Фильтры: media_type, q, genre_id и page. Анимация соответствует movie и genre_id=16. Номера страниц хранятся в URL фронтенда отдельно для каждой категории. Доступны страницы 1–500 в соответствии с API источника.

Ответы discovery содержат метаданные и TMDB ID без локального UUID (`id=null`). Клиент преобразует их в модель интерфейса с числовым id. Результаты не ограничены локальной БД и не импортируются при просмотре. Для поиска с жанром общее количество совпадений неизвестно: бэкенд возвращает total_results=null, интерфейс показывает навигацию по страницам без недостоверного счётчика.

Для числового ID страница фильма читает `GET /api/v1/discovery/movies/{media_type}/{tmdb_id}`. Для UUID она читает сохранённую карточку через `GET /api/v1/movies/{uuid}`. Все GET-запросы не меняют БД. Кэш и объединение одновременных обращений к TMDB реализованы на бэкенде.

## Действия пользователя

`src/api/library.ts` — серверный клиент API. `src/libraryActions.ts` предоставляет Server Actions для создания и выбора профилей, чтения коллекции и пользовательских действий. Новая карточка отправляется как media_type + tmdb_id, сохранённая — как UUID. Метаданные фильма не принимаются из браузера: бэкенд получает их из доверенного источника.

Добавление в избранное и оценка выполняются одним запросом. Бэкенд сохраняет отсутствующий фильм и действие в одной транзакции; фронтенд обновляет Zustand только после успешного ответа. Удаление использует UUID и не обращается к TMDB. Избранное и оценка независимы.

`libraryState.ts` хранит экранный кэш, состояние загрузки и ошибки. `GET /profiles/{id}/library` загружает полный снимок коллекции при выборе профиля или обновлении. Изменения возвращают отдельную запись и обновляют кэш без полной перезагрузки. Сейчас снимок не имеет пагинации; для больших пользовательских коллекций понадобятся отдельные постраничные методы.

При смене профиля данные сразу очищаются. Счётчик поколений запросов исключает подмену коллекции запоздалым ответом для предыдущего профиля. Во время записи переключение блокируется. Ошибка сервера отображается без подтверждения несохранённого действия и без подстановки прежних локальных данных.

В localStorage хранится только выбранный UUID (`kinoteka-profile-v1`). `legacyLibraryStore.ts` читает старую коллекцию `kinoteka-library-v1` без записи и удаления. На странице профилей перенос запускается явно, с указанием получателя. Записи объединяются по media_type + tmdb_id и отправляются пакетами по 10 (API допускает до 20). Каждый пакет атомарен; уже сохранённые пакеты остаются при сбое следующих. Повторный перенос безопасен: избранное не дублируется, существующая серверная оценка сохраняется. Исходная копия остаётся в браузере.

## Ошибки и конфигурация

API-клиент проверяет формат ответов, UUID, TMDB ID, относительные пути изображений и метаданные пагинации. 404 отличается от недоступности сервиса. Таймаут внешнего просмотра через бэкенд — 20 секунд, команды сохранения — 25 секунд, перенос пакета — 120 секунд, локального чтения — 8 секунд.

TMDB-ключ находится только на бэкенде. При недоступности TMDB свежий кэш продолжает отвечать до истечения срока жизни; после истечения отображается ошибка источника. Локальная библиотека и сохранённые карточки доступны независимо от TMDB при работающем бэкенде.

Текущая версия предназначена для локального использования. Перед внешним размещением API пользовательских действий и Server Actions должны проверять авторизацию.


## Рекомендации

`/recommendations` получает подборку через `getRecommendations` Server Action и профильный API бэкенда. Ответ содержит preview карточек, стратегию item_knn/content/hybrid/popularity, необязательную версию модели, количество известных оценок, происхождение элементов и состояние источников. Клиент проверяет структуру, уникальность фильмов и корректность числовых значений; score не показывается как вероятность или личная оценка.

Компонент результата привязан к UUID профиля и содержимому его оценок. Смена профиля или оценки размонтирует прежний результат; cleanup игнорирует запоздалый ответ. Ошибка имеет отдельную кнопку повторения. Базовая популярная подборка обозначается явно; неподдержанные моделью оценки остаются в коллекции.

Обучение и ранжирование выполняет Python-сервис. Фронтенд не хранит модель и не сопоставляет профиль с пользователями MovieLens. Отсутствие ML-артефакта не блокирует content/popularity; при degraded=true интерфейс показывает частичную недоступность источников. При недоступности метаданных карточки используют названия из датасета без постеров.

На странице доступны режимы «Для вас» и «Удиви меня». Второй отправляет `mode=surprise`, а кнопка «Ещё подборку» делает новый запрос без фиксированного seed. Во время загрузки повторная кнопка недоступна. Изменение режима, профиля или оценок создаёт новый экран результатов; поздние ответы предыдущего запроса игнорируются. API-клиент проверяет mode, seed, стратегию exploration и флаг exploratory. История показанных подборок в браузере не ведётся, поэтому между запросами возможны повторы. Подробнее об алгоритме — в документации рекомендаций бэкенда.

Обычный режим «Для вас» запрашивает до 30 фильмов, «Удиви меня» — до 10. Клиент проверяет размер ответа относительно лимита выбранного режима. Бэкенд допускает до 50 результатов в обычном режиме; фактическая подборка может быть короче при исчерпании подходящих кандидатов.

## Контейнер

Next.js собирается с output=standalone. Runtime-образ содержит server.js, его зависимости, public и .next/static; запуск выполняется пользователем node. BACKEND_API_URL=http://backend:8000 задаётся Compose при запуске, поэтому адрес не закрепляется в сборке и не передаётся браузеру. Общая схема компонентов и инструкции находятся в документации бэкенда: docs/system-design.md и docs/deployment.md.
